# Protocol references

Third-party GP-5 / GP-50 web editors that already solve connect, dump, and live control.

**Read** the local copy in `reference/` (GP-50 editor HTML) when encoding or decoding SysEx. Do **not** paste that JavaScript into `src/`. Implement Patone-owned codecs; match operator captures and Patone Log.

Useful observations (not a protocol spec):

- After connect they show a loading overlay (`Syncing with GP-50 …` / GP-5) and request a patch-name list, then the current patch index, then the current preset, then other dumps. Patone requests the IR-name dump once per connect, after the current-preset ask, and does not wait on it. Globals, preset-status, and NAM stay out. On patch change they request that preset dump again; Patone does not re-request IR names on Reload or patch change.
- Those asks share the identity-family SysEx template Patone already owns: name-list is size `0x0E` / command `0x00`, current-patch is size `0x07` / command `0x03`, current-preset is size `0x09` / command `0x01`. The IR-name request is the same 14-byte envelope with a distinct size and path: `F0 02 09 00 01 00 00 00 02 01 02 02 00 F7`. A GP-50 Bluetooth Patone capture of size `0x0E` / command `0x01` only returned a 16-byte ACK, not a dump.
- Inbound current-preset fragments differ by pedal and link. Bluetooth GP-50 uses command `00 06` (short terminator); GP-5 uses `00 05`. USB GP-50 uses `01 0B`; GP-5 uses `01 09`. Name-list dumps stay `01 05` (Bluetooth) / `06 0A` (USB) and must not be parsed as a chain.
- Bluetooth IR-name fragments use command `00 04` (F0-aligned lengths 210 data / 94 terminator; the reference editor's raw packets are 212 / 96 including the BLE-MIDI header). Twenty nibble-packed names start at payload offset 44 with stride 32. They must not be fed to the current-preset assembler. USB IR fragment command and length were not in a Patone Log at apply time; unknown USB headers stay fail-open (missing names keep `User IR 01`…`User IR 20`). Do not invent a USB header and do not paste `reference/` JavaScript.
- USB uses Web MIDI with SysEx enabled. Some live global/footswitch changes are not notified over USB.
- Bluetooth uses the BLE-MIDI GATT service and the same SysEx conversation, wrapped in BLE-MIDI packets. Host SET SysEx is one GATT write (`80 80` + full `F0`…`F7`), as in the accepted chain-order capture. Do not chunk a 38-byte `1147`/`1148` SysEx into 20-byte packets; the pedal ignores that.
- **Two families:** identity / live notify uses path `01 02 04` (checksum unknown). Parameter **SET** uses path `01 01 04`, CRC-8 ATM (poly `0x07`, init 0) of the packed body, then nibble-expand each hex digit to a `0x0n` MIDI byte (`src/device/sysex-nibble.ts`). Echoing a live notify is not a SET.
- Pedal chain-order **notify** (Patone Log, Bluetooth): size `0x0C` / command `0x04` / path `01 02 04`, 34 bytes, nibble-expanded `DUMP_MODULE_IDS` indices. Patone GP Studio applies it on Bluetooth (`liveFromPedal`). USB does not emit it and must not apply it.
- Pedal chain-order **SET** (accepted operator log, Bluetooth, PRE before NR): same 10-slot payload, path `01 01 04`, CRC `08 07` for that order. Packed body `01 00 0C 11 44` + ten dump indices. W1 (host `01 02 04`) and W2 (notify echo, checksum `00 00`) were ignored. Notebook: `openspec/changes/chain-reorder/spike-chain-order-write.md`.
- Current-preset **model + control** fields live in that same dump (wire identity + float32 LE per kind). App→pedal model write is packed family `1147`; control write is `1148`. Same CRC-8 + nibble-expand SET path `01 01 04`. Pedal→app live model is identity-family command `07`; live control is command `08` (path `01 02 04`). Patone GP Studio applies those on Bluetooth (`liveFromPedal`) and ignores them on USB. The reference editor debounce is 50 ms on slider `input`. Patone GP Studio updates the snapshot on every step and coalesces the `1148` SET (~80 ms throttle, flush on pointer-up) so BLE-MIDI is not flooded. Do **not** copy `reference/` JavaScript; match captures.
- Storing the working patch (Save / rename / duplicate onto another slot) is a parameter-write SET of packed family `114a` (path `01 01 04`, CRC-8 ATM + nibble-expand; not live notify `01 02 04`). Packed body carries destination slot 0–99 and a 10-character space-padded ASCII name. Operator capture: Save and duplicate-to-another-slot both store that destination index (not a display-only field). Do not encode a full preset dump if that SET is ignored. Patone GP Studio **download** encodes a Valeton `.prst` for the connected model from the assembled current-preset dump. Layout locked from `_reference/gp50_60-TOB.prst` / `_reference/gp5_60-TOB.prst`: 20-byte ASCII model header (`GP-50` / `GP-5` padded + `01 00`), CRC-8 ATM (poly `0x07`, init 0) of the rest, spacer `FF FF FF FF`, 10-byte NUL name (spaces as `00`), model descriptor, packed dump body. GP-50 descriptor follows the capture (not the truncated HTML constant). Patone GP Studio **upload** is the inverse of that layout into the working patch: decode the file, apply with owned working-buffer writes (model `1147`, catalog-control `1148`, chain-order SET, module CC 48–57). It does not send store `114a` and is not a dump SET. Save / rename / duplicate remain the store. Apply paces those SysEx (short gap after each write, longer after a model SET and before the dump refresh) because USB `send` and BLE-MIDI `writeValueWithoutResponse` both return before the pedal has applied the previous message; a burst drops trailing writes. Packed family `1142` patch volume/BPM (descriptor fields; dump words before the packed body) follows the reference black-box `sendPatchVol` / `sendBPM` body (`01 00 0a 11 42`…) and is sent as part of apply; there is no Patone accept capture yet. That SET stays the upload path. The patch bar does not use it: live volume is official CC 7 (0–100) and GP-50 tempo is official CC 73 then CC 74 (40–260). Inbound CC 7, CC 73, and CC 74 are not applied to the snapshot. Do **not** copy `reference/` source or payloads.

Movable chain modules: NR, PRE, MOD, DLY, RVB. DST, NS, AMP, CAB, EQ stay a contiguous block.

Patone GP Studio’s in-scope subset is current patch index, onboard names, the current preset’s audio chain (module order + on/off + factory model and control values for the ten effect slots, including the twenty user-IR CAB slots), the IR-name dump, Bluetooth live chain-order follow, Bluetooth live model/control follow, the order-only SET, model/control SETs of the same parameter-write family (`1147` / `1148`, including selecting a user IR slot), the current-patch store SET (`114a`), a connected-model Valeton `.prst` export of that dump, and current-patch `.prst` load into the working patch (inverse of the locked layout, owned writes, not a dump SET and not a store). Library browse/import/reorder, Library `.prst` import, cross-model conversion, IR / NAM **file upload**, the Editor route, and tuner stay out. Patch-bar volume (CC 7) and GP-50 BPM (CC 73/74) are in scope on USB and Bluetooth; inbound volume and BPM are not applied.

Stomp **assignment** (which modules each footswitch toggles) is a paused lab, not product: decode from the current-preset dump is locked for GP-50; SET candidates were ignored. Same CRC + nibble family as chain-order SET (`sendCTL` in the reference editor); H7 used the wrong size/command/body. Resume notes: `openspec/changes/stomp-assignment/spike-assignment-write.md`.
